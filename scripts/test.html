คู่มือสำหรับทีม Backend — หน้า Config (หน้าหลัก)

ศูนย์ควบคุมระบบ: จัดการแหล่งข้อมูล (Sources), กำหนดเวลารันอัตโนมัติ (Schedule) และกดรันเก็บข้อมูล (Collect)

1) Sources — จัดการแหล่งข้อมูล

MethodURLBodyความหมาย
GET/api/sources—ดึงรายการ source ทั้งหมด (เรียง created_at desc)
POST/api/sources{ platform, label, source_url, results_limit, model_provider, model_name }เพิ่ม source (201)
PATCH/api/sources/:idเช่น { active }แก้ไข / toggle เปิด-ปิด (badge On/Off คลิกได้)
DELETE/api/sources/:id—ลบ (200 { ok: true })

ฟิลด์ใน object: id, platform (facebook), label, source_url, results_limit, active, model_provider (typhoon|groq), model_name, created_at, updated_at

หมายเหตุ: แพลตฟอร์มเดียวที่รองรับคือ facebook (ผ่าน Apify); AI model ที่มี: typhoon (v2.5-30b / v2.5-7b), groq (llama-3.3-70b / llama-3.1-8b)

2) Schedule — กำหนดเวลารัน

MethodURLBody
GET/api/schedules—
POST/api/schedules{ hour, minute, label } (hour 0–23, minute 0–59)
PATCH/api/schedules/:idเช่น { active }
DELETE/api/schedules/:id—

ฟิลด์: id, hour, minute, label, active — เวลาเป็น UTC

3) Collect — รันเก็บข้อมูล (หัวใจของระบบ)

  • หน้าเว็บโหลด /api/sources → กรอง active === true → เรียก GET /api/collect?sourceId=<id> ทีละ source
  • Response เป็น { steps: [...] } หน้าเว็บฉายทีละบรรทัดแบบ real-time
  • Step สุดท้ายต้องเป็น { type: "summary", inserted, duplicates, low_confidence, errors, skipped }
typestatusแสดงผล
source_startrunningScraping <label> (limit: N)
pollok / รอScrape done (Xs) / Waiting...
fetchok / errorGot N posts (page X of Y) / fetch error
platform_skipped—<label> skipped — <hint>
iteminsertedSaved — type · area · province · district (conf%)
itemduplicateDuplicate (already in DB) / Duplicated post (repost) — NOT saved
itemlow_confidenceNot a listing (score: N) — NOT saved
itemerrorError: ... — NOT saved
time_limit—Time limit — processed X, skipped Y (next round)
summary—การ์ดสรุปตัวเลข (step สุดท้าย)

กฎ Backend: post_url ซ้ำ = duplicate; raw_post_text เหมือนกันเป๊ะ + จำนวนรูปเท่ากัน = repost (ไม่เรียก AI); confidence < 0.3 = drop; ใกล้หมดเวลา (60s) ให้บันทึก time_limit แล้วรันต่อรอบหน้า

4) Collect ทำงานอย่างไร (โดยละเอียด)

กดปุ่ม Collect Now → GET /api/collect?sourceId=<id> ไล่ทีละ active source (เรียงจาก /api/sources)

  1. Frontend (scripts/test.html): testCollect() → โหลด /api/sources → กรอง active → เรียก Collect ทีละ source → ฉาย steps[] แบบ real-time
  2. Backend (src/routes/collect.js): อ่าน sources จากตาราง source_configs (active=true) → จัดกลุ่มตาม platform → getCollector(platform) + ตรวจ isAvailable() (ถ้าไม่พร้อม = step platform_skipped) → เรียก collector.collect() → รวมผลเป็น step summary → saveRunLog() บันทึก lead_logs 1 แถว/รอบ
  3. Facebook collector (src/collectors/facebook.js):
    1. fetchSourceItems(): สั่ง Apify รัน actor apify/facebook-groups-scraper (proxy residential, extractPostDates) → poll ทุก 3 วิ จน SUCCEEDED (งบ 55 วิ) → getDatasetItems() ดึง posts
    2. mapApifyItem(): แปลงฟิลด์ — user.name→authorName, user.profilePic→authorUrl, attachments[].image.uri→imageUrls, time→createdAt, inputUrl→groupUrl
    3. processItems(): ประมวลผลทีละ 5 posts (BATCH_SIZE), push step batch_progress
  4. ต่อ post (processOneItem):
    1. Dedup: (a) post_url ซ้ำใน leads → duplicate/existing_url; (b) raw_post_text เท่ากันเป๊ะ + จำนวนรูปเท่ากัน → duplicate/repost (ข้ามโดยไม่เรียก AI)
    2. AI extract → extractProperty(text, {provider, model}) (อ่าน src/lib/groq.js + prompt ใน src/lib/prompts/extract-property.md)
    3. confidence_score < 0.3 → drop (low_confidence)
    4. โหลดรูป (max 10, timeout 15s/รูป) → อัปโหลด bucket lead-images (Supabase Storage)
    5. extractGoogleMapsUrl() — regex ฉกลิงก์ Google Maps จาก caption (ไม่ใช้ AI)
    6. assignAgentTeam() — ทีม A/B/C แบบ deterministic จาก province/district
    7. insertLead() → ลงตาราง leads
    8. processLeadForResult() → workflow result-leads (ดูด้านล่าง)
  5. AI ทำอะไร (src/lib/groq.js):
    • ส่ง system prompt + เนื้อหา post (ตัด 4000 ตัวอักษร) → {provider}.baseURL/chat/completions, temperature: 0.1, retry 3 ครั้ง (429/5xx/JSON ผิด)
    • Provider: typhoon (default, typhoon-v2.5-30b-a3b-instruct, ไม่มี JSON mode) หรือ groq (llama-3.3-70b/llama-3.1-8b, ใช้ response_format: json_object)
    • AI อ่านโฆษณาแล้วคืน JSON: property_type (Warehouse/Factory/Showroom & Commercial/Other), listing_status, ราคาเช่า/ขาย + unit (total/per_sqm) + พื้นที่อ้างอิง, ที่ตั้ง (province/district/sub_district/address), ข้อมูลติดต่อ (ชื่อ/เบอร์/Line/WhatsApp/WeChat), owner_or_agent, ai_summary (สรุปไทย 1-2 ประโยค), ai_tags, confidence_score (0-1)
    • computePrices() (src/lib/pricing.js): ถ้าราคาเป็น per_sqm → total = raw × pricing_area_sqm (เช่น "108 บาท/ตรม/เดือน" ไม่ใช่ราคารวม)
    • post ที่ไม่ใช่อสังหาฯ → confidence 0 → drop
  6. Prompt (src/lib/prompts/extract-property.md):
    • บทบาท: "You extract industrial property listing information from Facebook posts."
    • บังคับคืน JSON เท่านั้น (ไม่มี markdown); กฎราคา: per-sqm ≠ ราคารวม (ถ้า per-sqm → unit:"per_sqm" + raw + pricing_area_sqm, ปล่อย rent_price:null ให้ระบบคำนวณ; เช่าเป็นรายเดือนเว้นแต่ระบุรายปี)
    • Schema JSON 25+ ฟิลด์; ปิดท้าย "If the post is not a property listing, set confidence_score to 0."
  7. Workflow result-leads (src/workflow/result-leads.js):
    • isComplete(): ต้องมี sqm (อย่างน้อย 1 ใน pricing/land/building), province+district+sub_district, ≥1 รูป, ราคา, agent_team
    • สมบูรณ์ → snapshot ลง result_leads (normalize จังหวัด/อำเภอ/ตำบล)
    • หา duplicate: ตำแหน่งเดียวกัน + sqm เท่ากัน → compareAndMerge() ส่งรูปให้ vision (Groq qwen/qwen3.6-27b, prompt compare-properties.md, ≤2 รูป/ฝั่ง) → same_place && confidence ≥ 0.7 → merge เก็บโพสต์ที่สมบูรณ์กว่า
